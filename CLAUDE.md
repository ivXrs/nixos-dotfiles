# nixos dotfiles

flake with hosts `roxas` and `vm`. home-manager runs as a nixos module, so one rebuild applies system and user config.

## commands
run from the repo root.
- `nix flake check`: evaluates every host. must pass before reporting a change as done.
- `nix eval --raw .#nixosConfigurations.<host>.config.system.build.toplevel.drvPath`: evaluates one host; faster while iterating.
- `alejandra .`: formats all `.nix` files. run after editing. `alejandra --check .` only checks.

## forbidden
- do not apply changes: no `nixos-rebuild`, `nh os ...`, `home-manager switch`. the user applies them.
- do not run `install.sh`: it wipes disks.
- do not run `nix flake update` or edit `flake.lock` unless asked.

## repo structure

## architecture
- `hosts/<host>/configuration.nix` imports the top-level nixos modules it uses and sets `irene.*` options.
- layering: `modules/nixos/programs/<name>` (one program each) → `modules/nixos/suites/<name>` (enable groups of programs) → host enables suites. enable a new program from a suite, not from the host.
- `modules/home-manager/<name>` is loaded for every user via `sharedModules`; enable it in `homes/<user>/default.nix`.
- `irene.home-manager.enable` is the nixos-side integration switch, not a user module.
- reference repo files as `"${inputs.self}/..."`; `inputs` comes from `specialArgs`.

## adding a module
- copy `templates/module/default.nix`, replace `namespace.module` with the real option path, drop unused args.
- option paths: `irene.<name>` (top-level nixos), `irene.programs.<name>`, `irene.suites.<name>`, `irene.home-manager.<name>`.
- put all config under `lib.mkIf config.<option path>.enable { ... }`.
- modules are not auto-discovered: add them to the parent `default.nix` imports (`modules/nixos/programs/`, `modules/nixos/suites/`, `modules/home-manager/`). a new top-level `modules/nixos/<name>` must also be imported in each host's `configuration.nix` that uses it.

## gotchas
- `hosts/*/hardware.nix` is generated by `nixos-generate-config`; do not edit or create it.
- the flake only sees files tracked by git: `git add` new files before `nix flake check`.

## code style
- write descriptions and comments in english and lowercase. keep identifiers, commands, paths, option names and case-sensitive values as they are (`es_ES.UTF-8`, `EF00`, `LC_*`, package names).
- group attributes that share a prefix in one nested set (`irene = { boot.enable = true; users.enable = true; };`). a set with a single attribute is written as an attribute path (`programs.bat.enable = true;`, not `programs = { bat = { enable = true; }; };`). never define the same prefix twice in one set.
- avoid `let ... in`.

## agents
- exploration agents use `Explore` (`.claude/agents/Explore.md`): haiku with high effort by default.
- only raise the model or effort for a specific call when the task needs more intelligence, using the `model` or `effort` parameter of that call.
- never exceed the orchestrator's own model or effort. there is no native cap, so this rule is the only guard.

## git
- commit scope = module or host (e.g. `feat(programs): add bat`, `fix(hosts/vm): ...`).
- validation before committing: `nix flake check` and `alejandra --check .` must pass, and `repo-structure.md` must be up to date (regenerate it, then `git diff --exit-code repo-structure.md`).

## workflow
- before editing any file, explain the change, its purpose and impact, and wait for explicit confirmation.
- keep changes to the requested scope; no unrelated cleanup.
- finish with: modified files, validation results (claim success only if the command exited 0), remaining issues.
